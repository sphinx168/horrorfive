# 文本校對

這個遊戲的沉浸感有一半是介面撐起來的——玩家要相信自己開的是 2015 年那個免費空間上的爛留言板、和當年的 Yahoo!奇摩信箱。一個現代用語、一個半形逗號、一個沒被替換掉的佔位符，都會讓人瞬間想起自己在看網頁。所以文字在這裡不是文案問題，是**布景**。

這份 skill 分兩塊，可以只跑一塊，也可以整份掃：

- **第一塊：介面文字** — 不出自任何角色之口的字，寫死在 renderer 與資料表裡。
- **第二塊：文件內文** — 角色實際打出來的字，但只查**字本身**，不評口吻。

## 分工

| 這份 skill 管 | 交給別人 |
|---|---|
| 錯字、簡繁、標點形式、換行、佔位符、專有名詞、年代違和、版面極限 | 這句話「是不是那個角色會說的」→ `voice-check` subagent |
| | 日期、樓層編號、時間跨度、揭露順序 → `narrative-continuity` subagent |
| | 設計文件與實作的落差 → `design-doc-sync` subagent |

界線很好記：**標點的「形式」歸這裡，標點的「習慣」歸 `voice-check`。** 半形逗號混進中文是這裡的事；宗翰這句該不該收句號是那邊的事。兩邊各判一次會給出互相打架的結論。

**只讀不改。** 產出是一份問題清單，要不要動由使用者決定。使用者說改，才改。

---

## 第零步：機械掃描

先用 `Grep` 工具跑這幾條，它們抓的是人眼最容易漏掉的東西。有命中不代表就是錯（先看上下文），沒命中也不代表乾淨。

| 找什麼 | pattern |
|---|---|
| 簡體字 | `[这么说们发网点击视频邮电话时间问题实现开关来会对样过还进国图团东车长头马买卖]` |
| 中文之間的半形標點 | `\p{Han}[,.?;:]\|[,.?;:]\p{Han}`（已知例外：`Yahoo!奇摩` 是當年的正式寫法，`......` 是即時通存檔裡刻意的；`!` 不放進 class，否則整片 `Yahoo!` 洗版） |
| 板／版寫反 | `版主\|看版\|貼版\|板本\|留言版` |
| 現代／中國用語 | `登陸\|登錄\|賬號\|用戶\|信息\|視頻\|默認\|激活\|點贊\|上傳中\|加載` |
| 沒被替換的佔位符 | `__TODAY__`（見第二塊第 3 項，只有 `meta:` 上的才合法） |
| 半形刪節號與破折號 | `\p{Han}\.\.\.\|\.\.\.\p{Han}\|\p{Han}--\|--\p{Han}`（一定要用中文錨住，否則 CSS 變數 `--ink-soft` 會整片洗版；`......` 只有即時通存檔那一句是刻意的） |
| 分隔符沒用全形 | `\|` 兩側不是全形空格的地方（板首頁、站尾、信箱工具列一律 `　│　`） |

跑完再進人工檢查——機械掃描抓不到用語不一致、年代違和、劇透與版面爆掉。

## 第一塊：介面文字

### 落點

行號會隨改動漂移，用函式名或表名去找。玩家看得到的介面文字只有這幾個地方：

- **`<body>` 靜態 markup** — 登入頁（`五樓` / `EST. 2015` / 帳號 / 密碼 / 登入 / 那行 `本板不開放註冊　│　目前 6 個帳號`）、茶水間 App 外框（`title="收起茶水間"`、頭像的「茶」）、瀏覽器 chrome 的 `◀ ▶ ⟳`。
- **`CHAT_TITLE` / `CHAT_SUB`** — 群組名與成員列，畫在 `caTtl`。
- **`chatInBar()`** — `↑ 點上面那句話送出` / `輸入訊息…` / `送出`。
- **`showToast()`** — 推播的 `茶水間` / `有新訊息`；`syncApp()` 的浮球「茶」與未讀數。
- **`chatCard()`** — 聊天室裡的連結卡片：開場那張 `{u,url,lbl}` 的標題與網址、`share` 卡片抓的 `SITE` 標題與網址。這是玩家最早看到的介面文字之一。
- **`SITE`** — 每一個分頁標題與假網址。**兩者都是玩家看得到的字**，omnibox 印的就是 `SITE[active].url`（`GATES[].url` 從來沒有被畫出來，改假網址要改 `SITE`）。
- **`wlAd()` / `wlFoot()`** — 頁首廣告與站尾（訪客人次、文章數、最後發表、板主、Powered by）。站尾與側欄站內統計走同一支 `wlLast()`，標籤一律叫**最後發表**，不要一邊寫「最後更新」——那是 CMS 的詞，論壇說的是發表。部落格的 `subtitle` 是另一個站，那裡寫「最後更新」是對的。
- **`wlMast()` / `wlHead()`** — 板上每一頁共用的家具：站頭只有「五樓」兩個字，**刻意沒有副標也沒有標語**（那種板子不會替自己寫文案，空著比寫滿更像沒人在管），不要好心補上；導覽列（`論壇首頁　|　搜尋文章　|　精華區　|　板規`）、`目前身分：…`，以及公告條那句 `請勿張貼公司內部文件。發文前請先閱讀板規。`——**那是 2015 年就掛在那裡的舊公告，不是關站宣告**。這個板沒有被誰關掉，是沒有人再上來了；任何一句「本板已停止更新／已於某日停止發文」都會替那片沉默補上一個不存在的決定，也會把板主昱庭寫成關掉這個板的人。
- **`wlSide()`** — 側欄四格：板規摘要那四條、站內統計的欄位名（`討論主題` / `會員總數` / `今日文章` / `線上會員` / `最後發表`）、表情圖示的八個名稱、友站連結那四條與 `連結失效`。這些字在板首頁、討論串、搜尋結果三頁都看得到。
- **`renderBoardIndex()`** — 表頭（`主　題` / `樓層` / `人氣` / `最後回覆`）、`by …`、`[置頂]`、`NEW`、`文章列表`（五樓沒有分區，這張表列的是同一個板裡的文章，不是好幾個討論區）、`發表新文章` 與 `本板目前為唯讀，無法發表文章。`（唯讀是主機狀態，不要寫成某一天做的決定）、分頁器（`‹‹ 上一頁` / `下一頁 ››` / `共 N 頁`）。
- **`renderThread()`** — 樓層標籤 `NF`、`（你）`、`已還原`、`現在時間 …` 那行、`wl-sub` 那條 meta。
- **`renderArchive()`** — `Yahoo! Messenger 對話紀錄` 與檔尾那條 `C:\` 路徑。
- **`renderInbox()`** — 資料夾名（`收件匣` / `草稿匣` / `寄件備份` / `垃圾桶`）、`← 回信箱`、`寄件人` / `收件人` / `日期` / `附件：`、`這個資料夾是空的。`、頂欄 `YAHOO!奇摩　電子信箱` 與工具列 `信件　│　通訊錄　│　行事曆　│　登出`。
- **`renderBlog()`** — 站尾的 `沒有留言。` / `發表留言`。
- **`renderGate()`** — `記住我的帳號` / `忘記密碼？` / `密碼提示問題` / `送出` / 搜尋頁的 `搜尋`，以及 `GATES` 裡的 `brand`、`note`、`forgot.hint`、`nudge`、`err`、`fields[].label`、`fields[].prefill`。
- **`renderRestore()`** — 表頭（`所在討論串` / `刪除時間` / `刪除者`）、`還原已刪除文章`、`確認還原`、`請先選擇要還原的文章。`、`目前沒有可以還原的文章。`、`restoreMsg` 那句 `已還原。〈…〉那一樓現在看得到了。`
- **`showSearchResult()`** — 兩筆搜尋結果的標題、網址、摘要。
- **`renderSaid()` + `AFTER[].said`** — 過場旁白與「繼續」。
- **`renderEnd()`** — 結局全文。
- **`renderPage()`** 的 `找不到網頁`。

**不是玩家可見文字，不要報**：`GATES[].ch` / `label` / `need`（只有 `notesContent()` 會畫，而 `NOTES_TAB_ENABLED=false`，那個分頁是關著的）、`DOCS[].peek` / `lockTitle`（同上）、`DEV_STAGES` 與整個 `#dev` 面板、程式碼註解。

### 檢查項

1. **簡繁與錯字**——全篇繁體。特別盯 `板`（board）不可寫成 `版`：板主、板規、板務、主板、這個板。
2. **標點與全半形**——中文之間用全形標點；數字與英文前後留半形空格（`已超過 4000 天未登入。`）。分隔符一律 `　│　`。分頁標題用全形連字號 `－`（`五樓 － 整理`），散文用破折號 `——`，兩者不可互換。
3. **語氣層級**——系統句收句號（`密碼不正確，請再試一次。`）；按鈕、標籤、分頁標題、導覽列不收句號。新加的字串要照這條歸隊。
4. **用語一致性**——同一個東西全篇同一個叫法：帳號（非「賬號／用戶名」）、密碼（非「口令」）、登入／登出（非「登陸／登錄」）、還原（非「恢復」）、人氣（非「瀏覽量／點閱率」）、最後回覆、置頂、樓／`NF`。信箱四個資料夾是 2015 年 Yahoo!奇摩的實際用字，不可改成「寄件匣」「已刪除郵件」之類。
5. **年代**——這是 2015 年的免費空間 BBS 與當年的入口網站信箱。不可出現扁平化以後才有的介面語（「載入中」「一鍵」「深色模式」）、emoji（信箱那個 📎 是既有例外）、或任何 2016 年以後才存在的服務名。廣告與站尾的俗氣是刻意的，不要當成問題報。
6. **不可劇透**——分頁標題、假網址、關卡 `note` 與 `forgot.hint`、搜尋結果摘要，都是玩家在解開謎題**之前**就看得到的字。它們不可以比對應 `at` 的內容先說破事情。`SITE[].tab` 抄自串名，改串名時要一起看。
7. **版面極限**——遊戲是桌機專用，整個畫面鎖在 `#desk` 那個 4:3 的方框裡（最寬 1200px），寬度不會再變，所以沒有「窄螢幕」這回事；要顧的是這個固定寬度本身。板首頁的表格右邊三欄是定寬的（樓層 58px、人氣 58px、最後回覆 132px），`最後回覆` 那格排成上下兩行且 `white-space:nowrap`——名字變長或日期格式一改就會把那一欄撐開。側欄固定 274px，站內統計與友站連結的字一長就會折行。分頁標題目前最長 14 字（`五樓 － 這個月開會改到禮拜三`），再長會擠掉別的分頁。

## 第二塊：文件內文

### 落點

- **`CHAT`** — `steps[]` 裡的 `c`（訊息本文，含 `{me}` 草稿）、`sys`（系統／沉默行）、`lbl`（連結卡標題）。
- **`DOCS` skin `wulou`** — `title`、`meta`、`idx.label`、`posts[]` 的 `c`、`t`、`silence`。
- **`DOCS` skin `archive`** — `meta`、`days[].d`、`days[].lines[]` 的說話者與內容。
- **`DOCS` skin `inbox`** — `acct`、`mails[]` 的 `subj`、`body`、`att`、`fromFull`、`toFull`、`to`、`date`。
- **`DOCS` skin `blog`** — `title`、`subtitle`、`entries[]` 的 `d`、`t`、`b`、`gap`。

### 檢查項

1. **錯別字與簡繁**——跑第零步，全檔一起掃。中文間的半形標點在對白裡同樣算問題，但**刻意的例外要先看上下文**：即時通存檔的 `......`、冠廷那種不收尾的句子、當年那種重複標點，都是設計，不是錯。
2. **標點形式**——引號用「」與『』，不用 `""` 或 `''`；刪節號用 `…`（或存檔裡那種 `......`），不用 `...`；破折號 `——`，不用 `--`。**不判該不該有句號**，那是 `voice-check`。
3. **`__TODAY__` 佔位符**——只有 `renderThread` 的 `d.meta` 會經過 `T()`。寫在貼文內文、信件、聊天、部落格裡的 `__TODAY__` **不會**被替換，玩家會直接看到那八個字。全檔 grep，任何一個不在 `meta:` 上的都是 bug。
4. **換行**——`\n` 只有在 `white-space:pre-wrap` 的元素裡才有效：聊天泡泡 `.pl-bub`、板上貼文 `.rp .c`、信件內文 `.mbody`、部落格 `.bl-post .bd`、關卡 `.form .note`、旁白 `.said p`。**即時通存檔的 `.ar td` 沒有 pre-wrap**——`days[].lines` 裡寫 `\n` 只會塌成一個空格，要斷行就拆成兩行 line。
5. **專有名詞**——全檔同一個寫法：茶水間、五樓、一個人的公休日、昇岳資訊、人事名冊_9月.xlsx、Yahoo!奇摩。人名與帳號分工：角色互相稱呼用名字（思妤、昱庭），帳號 id 只出現在板上的署名、信箱位址、後台紀錄這些系統欄位裡——對白裡冒出 `ytl_lin` 幾乎都是寫錯了。
6. **年代語感（分兩層，別搞混）**——`DOCS` 是 2015 年的台灣網路中文：XD、Orz、注音文、`囧` 都對；不可出現 2016 年以後才有的流行語、服務名或簡體圈用語。`CHAT` 是 **2026 年**同一群人，已經四十幾歲了——他們不會講當年的火星文，也不會講年輕人的網路梗，那種年紀的人打字就是短、平、直接。
7. **殘留與空洞**——空字串（`c:''`）、同一句重複兩次、只有全形空格的行、行尾多餘空白、複製貼上沒改乾淨的名字或日期。

## 報告

依嚴重度排序（會破壞沉浸感或劇透的排前面，格式不一致排後面）。每一項寫成：

- **位置** — `五樓_單人版.html:行號`，加上是哪一個函式／表的哪個欄位
- **現況** — 把那段字原樣引出來
- **問題** — 屬於上面哪一項，以及玩家會看到什麼
- **建議** — 直接可貼的替代字串；拿不準就寫兩個選項並說明取捨

沒有問題就明講「沒有發現問題」，不要湊數。
