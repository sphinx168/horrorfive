# 各資料結構的形狀與範本

欄位都以 `五樓_單人版.html` 現行實作為準。照抄範本改內容，不要自己發明欄位名。

---

## 一、`CHAT`：茶水間（今天）

```js
{id:'c_xxx', when:()=>prog>=N, steps:[
 {u:'kt0904',  c:'一般訊息，會先跑「輸入中」動畫'},
 {u:'kt0904',  c:'第一行\n第二行'},              // \n 換行
 {u:'kt0904',  c:'開場墊場才用，不跑動畫',now:1},
 {me:'虛線草稿泡泡：停在這裡等玩家點下去才繼續'},
 {u:'yalin_w', share:'t_sort'},                  // 貼一份 DOCS 連結，點得開
 {u:'kt0904',  url:'http://…', lbl:'五樓'},      // 純網址卡（目前只有開場那個）
 {sys:'—— 沒有人接話 ——'},                       // 置中的系統／沉默行
 // 選擇泡泡：播放停下來，玩家挑一句送出。選到的記在 picks[ask]
 {ask:'letter', prompt:'那封信要不要講', opts:[
   {c:'沒有', v:'hide', then:[                    // then＝這個選項專屬的後續，選完插到最前面
     {u:'kt0904', c:'喔'},
     {sys:'—— 你沒有把那封信貼出來 ——'}
   ]},
   {c:'他有寄過一封信給我', v:'tell', then:[ /* … */ ]}
 ]},
 {me:'最後一句：送出即進終幕', end:1}            // end 也可以掛在某個 opts[] 選項上
]}
```

**`when()` 可以用的條件**（現行十五段用過的全部）：

| 寫法 | 意思 |
|---|---|
| `()=>true` | 一開場就播 |
| `()=>loggedIn` | 登入之後 |
| `()=>prog>=3` | 過到某一章 |
| `()=>seen.has('a_im')` | 玩家打開過某份文件 |
| `()=>mailRead.has('ytl')` | 玩家讀過某封信 |
| `()=>chatDone.has('c_found')&&blogRead` | 前一段播完，且部落格已捲到底 |
| `()=>adminIn` | 玩家登入了板務後台（`g_admin` 的前半段） |
| `()=>…&&endReady()` | 五份關鍵證據都真的點開過（終幕的門檻） |

**要點**

- `id` 不可重複（以 `id` 去重，重複的那段永遠不會播）。
- 每段只會觸發一次，觸發後整段排進佇列。
- `{me}` 是節奏工具：讓玩家自己把某句話「說出口」。她說得越不情願的話，越該做成草稿泡泡。
- 思妤自己的訊息用 `{u:'siyu_1120',c:…}`（直接浮現，不跑動畫）或 `{me:…}`（要玩家點）。
- 需要角色在某一段之後才出現在分頁上的閘，用 `GATES[].needChat:'c_xxx'`。
- **選擇泡泡（`{ask,prompt,opts}`）留給玩家真的要承擔的決定**，不是拿來當「下一頁」。
  現行三顆：10/14 那天是誰在打字（`who1014`）、要不要說出那封求助信（`letter`）、
  終幕最後那一句（`final`）。選項要能真的改變後面的東西——`then` 裡的反應、
  或 `renderEnd` 依 `picks.final` 換掉的那一段——否則就不要做成選擇。
- **角色不要搶在玩家前面說出答案。** 該由玩家想通的事，寫成 `{me}` 或 `{ask}`，
  讓那句話從玩家手上送出去；旁白（`AFTER[].said`）只描述畫面上發生了什麼。

## 二、`DOCS` skin `wulou`：留言板舊串

```js
{id:'t_xxx', at:1, skin:'wulou', site:'五樓',
 peek:'五樓　找不到這個頁面',            // 選填，鎖住時的假錯誤訊息
 filler:1,                               // 選填，跟主線無關的背景閒聊（板首頁顯示成灰字）
 top:1,                                  // 選填，置頂（目前只有 t_rules）
 title:'[整理] 她',
 idx:{f:'31F', by:'haoge', when:'2015/10/26', ts:TS(2015,10,26), hits:512},
 meta:'五樓 › 整理　│　2015/09/28 – 2015/10/26',
 posts:[
  {f:'1F', u:'tsonghan', c:'內容', t:'09/28 10:12'},
  {f:'14F',u:'siyu_1120',c:'第一行\n第二行', t:'10/05 09:41'},
  {f:'20F',u:'kt0904',   c:'這一樓要到第二章才長出來', t:'10/20 22:10', at:3},
  // 刪除樓 + 它還原後的樣子，兩筆共用同一個 rid：
  {f:'',   u:'', c:'此文已由作者刪除', del:1,
   rid:'r_kt', rdel:{when:'2015/10/26 18:40', by:'作者', ts:TS(2015,10,26)}},
  {f:'—',  u:'kt0904', c:'還原之後才看得到的內容', rid:'r_kt', t:'10/26 18:38'}
 ]}
```

| 欄位 | 說明 |
|---|---|
| `idx` | 板首頁那一行。`f` 總樓數、`by` 最後回覆者、`when` 顯示日期、`ts` 排序鍵（**全板不可重複**）、`hits` 瀏覽數 |
| `meta` | 串頂的那行小字，年份區間要跟 `posts` 實際範圍講得通 |
| `posts[].at` | 選填。這一樓要到某個 `prog` 才出現（分批滴入用） |
| `posts[].rid` | 刪除樓與其還原內容的配對鍵。**兩筆缺一不可**，只有 `del` 沒有還原內容的話，板務後台還原出來會是空的 |

樓層編號 `f` 在串內必須遞增；`idx.f` 不可小於串內出現過的最大樓層。

## 三、`DOCS` skin `inbox`：Yahoo 信箱

新的信件加進 `m_box.mails`，**不要另開文件**。

```js
{id:'yalin_hr', box:'in', at:1,
 from:'yalin_w', fromFull:'yalin.wang@shengyue.com.tw',
 date:'2015/10/05 14:47', subj:'張副理',
 body:'內文\n\n段落之間空一行。',
 att:'人事名冊_9月.xlsx　（12 KB）',   // 選填，附件名
 attDoc:'a_im',                        // 選填，附件點得開時指向的 DOCS id
 unread:1}                             // 選填，未讀
```

寄件備份／草稿匣用 `to` / `toFull` 取代 `from` / `fromFull`：

```js
{id:'siyu_draft1', box:'draft', at:1,
 date:'2015/10/10 01:32', subj:'（無主旨）',
 to:'周映柔', toFull:'yr.chou@shengyue.com.tw',
 body:'…'}
```

`box` 四選一：`in`（收件匣）／`draft`（草稿匣）／`sent`（寄件備份）／`trash`（垃圾桶）。

## 四、`DOCS` skin `archive`：Yahoo! 即時通存檔

新的一天加進 `a_im.days`，按日期排。

```js
{d:'2015/10/14', lines:[
  ['阿哲','妳今天在公司還好嗎！'],      // 第三個元素省略 = 阿哲（也就是思妤）那一側
  ['映柔','還好啦 就是有點累', 1]        // 1 = 對方（映柔）那一側
]}
```

寫這裡的每一句，先讀 `SKILL.md` 的語氣段：**阿哲的打字習慣必須等於 2015 的思妤**。

## 五、`DOCS` skin `scan`：手機拍的紙

冠廷從那個箱子裡翻出來、拍下來傳進群組的東西（目前只有 `d_box`）。

```js
{id:'d_xxx', at:5, skin:'scan', site:'相簿',
 title:'冠廷傳來的三張照片',
 meta:'2026/11/27 22:14　│　黃冠廷　│　3 張　│　未壓縮原檔',
 shots:[
  {cap:'照片底下那行說明', hand:0, lines:['一行','一行','']},   // '' = 空一行
  {cap:'手寫那張', hand:1, lines:['正常的一行','~被他劃掉的一行~']}
 ]}
```

`hand:1` 換成手寫的樣子（楷體、微微歪斜）；`~…~` 包起來的整行在畫面上會被劃掉。
劃掉的行是這個 skin 最有用的地方：**寫壞了幾次，比寫了什麼更說明他當時的狀態。**

## 六、`DOCS` skin `blog`：部落格

新的一則加進 `blog.entries`，時間由上往下遞增。

```js
{d:'2019/08/03', t:'公休日', b:'內文\n\n段落之間空一行。'}
{gap:'—— 這中間沒有任何文章 ——'}      // 用來表現斷掉的那幾年
```

標題不確定要寫什麼就用 `t:'（無標題）'`——那本身就是狀態的一部分。
別忘了同步 `blog.subtitle` 裡的「最後更新」日期。

## 七、新開一道閘（`GATES` + `AFTER`）

```js
// GATES
{id:'g_xxx', ch:'第三章', label:'checklist 上的一行字',
 site:'五樓', skin:'yahoo'|'admin'|'restore'|'search',
 url:'http://…', brand:['標題','副標'],
 note:'登入框上方的說明文字',
 need:'checklist 上的提示',
 needChat:'c_xxx',                    // 選填：這段聊天演完，分頁才會出現
 fields:[
  {label:'帳號', prefill:'…', locked:true, remember:true},
  {label:'密碼', type:'password', answer:['正確答案','可接受的其他寫法']}
 ],
 forgot:{hint:'「忘記密碼」點下去看到的東西'},
 nudge:{'常見錯答':'針對這個錯答的專屬提示'},
 err:'一般錯誤訊息'}

// AFTER：過關之後
g_xxx:{unlockAt:N, said:'過關後的全螢幕旁白，可留空字串'}
```

`answer` 用 `match()`／`norm()` 比對，全形半形、空白、大小寫、標點都會被正規化——列出玩家「意思對但寫法不同」的所有寫法即可，不必窮舉錯字。

`unlockAt` 是新的 `prog` 值，**一定要有一段 `CHAT` 在 `when()` 裡等它**，否則破關之後群組會是安靜的（hook 會擋）。

**先問這道閘值不值得存在。** 現行只有三道，而且第三道（`g_admin`）自己就是兩步：
登入表單（`ADMIN_LOGIN`，翻 `adminIn`）→ 同一個分頁換成還原清單。原本板務後台是
一道獨立的閘，玩起來就是「開一個空登入頁、回信箱抄一組密碼、再回來貼上」——
多一次操作，卻沒有多一分推理，所以被併掉了。
**推理量要放在證據比對上（見 `c_im` 的語氣比對），不是放在密碼欄。**
