# 新增劇情

《五樓》的文本散在五種資料結構裡，每一種都有自己的形狀與硬規則。這份 skill 把「寫一段新內容」的整套落地流程固定下來，避免每次都要重讀 `CLAUDE.md` 與整份 `五樓_單人版.html` 才敢動筆。

**開工前先讀**：`恐怖留言板遊戲_idea.md` 的 §一（故事）、§二（五個人的動機）、§四（線性揭露鏈）。那份文件是敘事真理來源，這裡只管怎麼把它落成資料。

---

## 第一步：決定這段內容屬於哪一層

這是最常出錯的一步，而且錯了要整段重寫。

| 這段內容發生在 | 放哪裡 | 理由 |
|---|---|---|
| **今天**（2026/11/27） | `CHAT` | 這五個人有一個天天在用的群組。沒有人會為了討論今天的事，回去一個十一年沒動過的舊留言板發文。 |
| **2015 年（或 2015–2025 之間）** | `DOCS` | 留言板現在是死檔案室，只承載當年留下來的東西。 |

留言板上唯一還有「後來」的痕跡是每年 11/27 的年度點名（`t_reunion`），而它是 `filler:1` ——刻意寫成沒有懸念的死路。**不要再往板上加任何「今天」的貼文。**

新內容還要決定它屬於哪一個章節，也就是它的 `at` 值：

```
prog 0 序章  →  1 第一章（過 g_mail）  →  2（過 g_ytl）  →  3（過 g_admin）  →  5（過 g_search）  →  6 終幕
```

`at` 只能是 **0 / 1 / 2 / 3 / 5 / 6** 其中之一（`prog` 4 從來沒有被指派過）。填別的值，玩家永遠看不到這份文件，hook 會擋下來。

## 第二步：寫進對應的資料結構

各 skin／各結構的完整欄位與範本見 [references/skins.md](references/skins.md)。這裡只列每一種的落點：

- **`CHAT`（茶水間，今天）** — 一段 scene = `{id, when(), steps:[…]}`，寫在 `const CHAT=[` 裡，位置照時序排。
- **`DOCS` skin:`wulou`（留言板舊串）** — 一整串討論。
- **`DOCS` skin:`inbox`（Yahoo 信箱）** — 不要新開文件，往既有的 `m_box.mails` 裡加一封信。四個資料夾 `in`／`draft`／`sent`／`trash` 都可以用。
- **`DOCS` skin:`archive`（即時通存檔）** — 同理，往 `a_im.days` 裡加一天。
- **`DOCS` skin:`blog`（部落格）** — 往 `blog.entries` 裡加一則，時間順序由上往下遞增，中間可以插 `{gap:'—— 這中間沒有任何文章 ——'}`。

## 第三步：六項落地檢查

新開一個 `DOCS` 文件時，這六件事一件都不能漏：

1. **`SITE` 註冊** — `SITE[新id] = {tab, url, fav}`。漏了，分頁標籤與網址會是空白。hook 會擋。
2. **論壇串要有 `idx`** — 沒有 `idx` 的 `wulou` 串不會出現在板首頁，等於玩家找不到。hook 會擋。
3. **`idx.ts` 不可與任何既有串重複** — 用 `TS(年,月,日)`。重複的話板上先後次序不穩定。hook 會擋。
4. **`idx` 三個欄位要自洽** — `idx.by` 是最後一樓的發文者，`idx.when` 對得上那一樓的日期，`idx.f` 不小於串內最大樓層。
5. **新的 `prog` 值要有 `CHAT` 反應** — 如果這段內容伴隨一道新的閘（`GATES` + `AFTER`），那個 `unlockAt` 一定要有一段 `CHAT` 在等它，否則破關之後群組是安靜的。hook 會擋。
6. **發話者要在 `USERS` 裡**（聊天室還要在 `AVATARS` 裡）。hook 會擋。

> 前面幾項寫著「hook 會擋」的，是 `.claude/hooks/check-five-floor.mjs` 在存檔當下就會退回並說明原因。剩下的靠自己。

## 第四步：硬規則（不會有人擋你，但壞了很難查）

- **自足性**：不可引入任何外部資源。整支檔案要能用 `file://` 離線打開。
- **繁體中文**，全形標點。時間格式照既有：串內樓層 `t:'11/20 22:39'`，信件 `date:'2015/11/20 22:47'`，部落格 `d:'2016/01/09'`。
- **不要在文本裡直接寫今天的日期**，需要時用 `__TODAY__`，`T()` 會替換成 `TODAY` 的格式。
- **揭露順序**：一個關鍵事實（例如「那晚幫思妤頂的是林昱庭」）不可以出現在它該被揭露的 `at` 之前的任何一份文件裡。這是最容易在補寫對白時破功的一條。
- **不要覆述正典台詞**：`t_stop`／`t_after`／`ytl` 那封信裡已經寫死的句子，聊天室裡的人回憶時只能講「大意」，不要逐字重複——他們的記憶本來就該兜不攏。
- **關鍵字母體**：板上的閒聊串是 `g_search` 關鍵字搜尋得以成立的雜訊來源。新加的 `filler` 串要跟劇情關鍵字（張副理／tsche0710／阿哲／員編／照片）**完全不沾邊**，也不要用刪除樓、分批貼文這些真線索才有的手法。

## 第五步：語氣

寫完的每一句都要能被念出來是「那個人」在說話。速查：

| 帳號 | 名字 | 句號 | 招牌 |
|---|---|---|---|
| `tsonghan` | 宗翰 | **幾乎每句都有。** | 冷、短、否定句；「我只是在陳述事實。」 |
| `haoge` | 文豪 | **幾乎每句都有。** | 命令式、只管流程；「丟掉。」「不要私下傳。」 |
| `ytl_lin` | 昱庭 | 陳述事情時有 | 遲疑、體貼、不高聲；「我覺得不太好」「欸 不要這樣啦」 |
| `kt0904` | 冠廷 | **從不用** | 「欸」「啦」「哈哈哈」「幹」；句子不收尾 |
| `yalin_w` | 雅琳 | **從不用** | 極短，常常只有一到三個字：「在」「嗯」「丟掉比較好」 |
| `siyu_1120` | 思妤 | **從不用** | 見下方 |

**思妤有兩個時態，寫錯就毀掉整個伏筆：**

- **2015 板上的她**：`！！`、`XD`、`^^`、`QQ`，熱切、討好。
- **今天聊天室的她**：那些全部消失，改用 `……`，句子隨劇情推進越來越短。
- **即時通裡的「阿哲」**：說話方式必須跟 **2015 的思妤** 一模一樣（`！！`／`XD`／`^^`／從不用句號）。**這是全遊戲埋得最深的線索**——玩家要能自己發現打字的人是誰。給阿哲寫任何新台詞時，這一條優先於一切。

寫完交給 `voice-check` subagent 複查。

---

## 第六步：寫完之後

1. 存檔時 hook 會自動跑資料一致性檢查，有問題會直接退回。
2. 跑 `voice-check` subagent 校語氣、`narrative-continuity` 校時序與揭露順序。
3. 動到關卡流程、`prog` 推進或章節結構的話，再跑 `design-doc-sync`，並把定案回寫進 `恐怖留言板遊戲_idea.md`。
4. 實際試玩：開 `五樓_單人版.html#dev`，用除錯面板跳到相關的那一站，確認新內容真的出得來、聊天室節奏不卡。
